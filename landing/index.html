Tell your shell what you want.

cook is an AI agent for your terminal. It reads files and runs commands to get the job done, and asks before it changes anything. One binary, any model.

$ curl -fsSL https://getcook.dev/install.sh | sh

For macOS, Linux and Windows (Git Bash). Then run cook on its own to pick a model.

Works the way your shell does.

Quotes are optional. Pipe things in, script it, run it from cron.

# plain words
$ cook find all TODO comments and summarize them

# pipe anything in
$ git diff main | cook "write a changelog entry"

# run a saved prompt
$ cook /create-pr

# see what would change first
$ cook --dry-run "refactor the auth module"
Saved prompts become commands
Put a prompt in .cook/commands/deploy.md and run cook /deploy. Your Cursor, Claude and Codex command folders work too.
An agent for each job
Give agents different models and prompts, then pick one with --agent fast.
Nothing else to install
cook is a single executable. No Node, Python or other runtime.

Set it up without the docs.

Run cook with no arguments to open the setup screen, then type / to see what you can change.

/model [provider] [id]
Pick a provider, then a model from its live list. For the Vercel AI Gateway that's 300+ models with context size and price.
/settings
API keys, steps, timeouts, confirmations, prompt files and every other option, with the file each one comes from.
/keys
Paste API keys. Input is masked and the config file is readable only by you.
/agent [name]
Switch the default agent, or create one from the current setup.
/scope global|local
Save to ~/.cook for everywhere, or to this project only.
/login
Sign in with ChatGPT to use the models your plan includes.

Type anything else and it runs as a normal task. The setup screen only loads when you run cook on its own, so cook "your task" starts as fast as it always has.

Nothing changes without a yes.

Reading is free. Writing, editing and anything destructive stops and asks first.

  • Every change asks first. Answer y, n, a for the rest of the run, or type what to do instead.
  • The model flags risky commands. Each command is classified as it's planned, not matched against a regex list.
  • It stays in this folder. File access is limited to the current directory unless you pass --allow-outside-cwd.
  • Preview with --dry-run. See the full list of changes without running any of them.
  • Keep a record. Turn on session logs to save every run and render it as an HTML report.
